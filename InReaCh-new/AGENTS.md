# InReaCh-new 协作与复现规则

## 目标与边界

- 本目录用于从零重写和理解 ICCV 2023 的 InReaCh；不要混入 Online-InReaCh 的算法或论文指标。
- `../InReaCh-main/` 是现有项目，`baseline/` 是创建本目录时的快照。两处都作为参考；新版代码应写在本目录的新实现中。不要修改快照、旧项目、数据集或旧结果来掩盖新版问题。
- 当前已实现最小图像输入模块，模型尚未重写。进度以 `docs/REFACTOR_LOG.md` 为准，不要把规划写成已完成。
- 上级 `../AGENTS.md` 提供旧项目背景，其中部分机器路径和硬件信息属于历史记录；运行前以当前机器的实际检查为准。

## 面向初学者的工作方式

- 每一步先用中文说明：这段代码解决什么问题、输入和输出是什么、为什么需要它，再写代码。
- 一次只引入一个主要概念或一项可检查的功能；代码中为形状变换、坐标顺序和关键算法写解释原因的注释。避免逐行重复 Python 语法。
- 每一步都记录改动文件、验证命令与实际输出；失败也如实记录。不要只说“应该可以运行”。
- 若改变论文算法、特征节点、预训练权重、训练/测试划分、输入预处理或评估口径，单独说明与原版的差异及其对结果的影响。

## 输入尺寸约定

- 当前第一步固定复现论文的 `256×256` 缩放与 `224×224` 中心裁剪，保持代码最小化。后续若比较其他输入尺寸，再明确配置 `height` 与 `width`，并保证一次实验内尺寸一致。不要写死 pic1 原图尺寸。
- 统一记法：NumPy 图像 `(H, W, C)`；OpenCV `resize` 参数 `(W, H)`；PyTorch 输入 `(N, C, H, W)`；特征网格 `(Hf, Wf)`。
- 长方形特征图必须使用真实的 `(Hf, Wf)` 恢复热图；不得用 `sqrt(块数)` 猜测边长。位置编码、掩码映射和输出缩放也应分别使用高度与宽度。
- 缩放、裁剪、补边会以不同方式改变图像内容；任何裁剪或补边都必须同步变换标注。保留长宽比及是否缩放都应写入实验配置。
- 计算量随图像尺寸和特征块数量增加。若为省显存缩小特征图，要记录该处理及其对检测小缺陷的潜在影响，不能把它称作“原尺寸完整特征”。

## 实验与环境

- 记录 Python、PyTorch、torchvision、NumPy、OpenCV、FAISS 版本，以及 GPU 型号和可用显存。不要直接使用旧 `requirements.txt` 或 `conda_inreach.yml` 安装：前者有 `fiass-cpu` 拼写错误，后者包含旧机器的绝对路径及混杂的 CUDA 依赖。
- 先验证图像可读与输入形状，再验证模型加载及一张图的特征形状，然后做小样本端到端，最后才跑完整实验。导入模块成功不代表模型加载或检测成功。
- 明确并检查 BGR/RGB 通道顺序、ImageNet 归一化、模型 `eval()` 状态、随机种子、参考图与测试图名单，以及标签类型。
- 当前图像输入代码不读取或变换 pic1 的 YOLO 框。后续若使用该数据集评估，应另行确认参考集构成和指标口径。
- 保存原始分数与参数，使用明确定义的指标比较尺寸方案。热图颜色和文件数量只能用于展示与运行检查，不能代替检测准确率。
- 大型数据、权重、缓存和结果不要复制进新版源码目录；路径通过配置传入。不要在日志中输出大数组或整套特征。

## 每一步的记录格式

在 `docs/REFACTOR_LOG.md` 增加一节，写明日期、目标、文件、与基线的区别、输入数据、固定参数、运行命令、退出状态或指标、已知限制和下一步。若新步骤推翻旧结论，保留旧记录并解释原因。
